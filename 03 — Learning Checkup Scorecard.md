# 03 — Learning Checkup Scorecard

This scorecard converts discovery findings into a simple current-state assessment of the Moodle learning ecosystem.

It helps the project team identify what is working, what needs improvement, and which issues should be considered for the 10-day roadmap.

Use the findings from **[02 — Client Discovery](https://github.com/hernandez-jc/Design-for-Change-Consulting-Toolkit/blob/c38f5fed710ce717e3d7f7ff6a697b4568880d49/02%20%E2%80%94%20Client%20Discovery.md)** to complete this scorecard.

---

## How to use this scorecard

1. Review one assessment area at a time.
2. Use discovery notes, Moodle reports, examples, and stakeholder input as evidence.
3. Assign a maturity rating from 1 to 5.
4. Record the main strength, gap, and evidence for each area.
5. Identify whether the issue is a possible quick win, foundational improvement, deferred item, or out-of-scope item.
6. Carry high-priority findings into the **Barriers and Constraints** log and **Prioritization Matrix**.

The scorecard is a decision-support tool, not a formal audit. Ratings should be based on available evidence and agreed interpretation.

---

## Maturity scale

| Rating | Level | Description |
|---|---:|---|
| 1 | Initial | The area is unclear, inconsistent, or not actively managed. |
| 2 | Developing | Some practices exist, but they are incomplete or inconsistently applied. |
| 3 | Defined | Basic practices are defined and used in most relevant areas. |
| 4 | Managed | Practices are consistent, monitored, and supported by clear ownership. |
| 5 | Optimized | Practices are effective, reviewed regularly, and adapted as needs change. |

7. Integrations and interoperability

## Action types

| Action type | Meaning |
|---|---|
| **Quick win** | A practical improvement that can be started or completed within the 10-day roadmap. |
| **Foundational improvement** | An important change that improves adaptability, quality, or governance but may require more coordination. |
| **Deferred item** | A valid issue that should be addressed in a later improvement cycle. |
| **Out-of-scope item** | An issue that requires a separate project, decision, budget, or specialist input. |
